# 使能落稳与版本加载修正

用户指出使能时少量抖动是正常现象。原接管立即按0.2°判停，混淆使能落稳与正式运动跟随误差。本次把两阶段拆开。

仅刚使能的一轴在固定2.5秒内允许相对原q0最多3°、转速最多3RPM；其他轴仍保持0.2°/0.3RPM。电流、温度、原始通信验证与急停检查保持。落稳要求连续至少0.4秒的采样位置总范围不超过0.1°且转速不超过0.3RPM，避免把缓慢持续漂移当作稳定。落稳后以该轴新鲜位置更新本轮q0、重发受限CB参考点，并恢复原严格复核。准备阶段固定总预算30秒，不无限等待。

“全局电流参数0 + CB20mA”不再在用户消息中宣称无转矩。旧事件名保留兼容，新`position_probe_enable_settled`事件记录实际设置、落稳偏移与耗时。

新增按SHA版本加载微动适配器：只在新worker开始时加载允许的`y42_position_microprobe_io.py`。不reload主程序，不替换STATE/锁/已有worker；旧worker保留旧模块。语法或入口检查失败取消本轮，通过现有失能收尾处理；不会悄悄运行旧版本。依赖模块和主进程本身不属于此热更新范围。

首次安装加载入口已在四轴失能、无活跃记录条件下正常重启完成，COM5/921600四轴自动准备通过，无需用户手动结束进程。后续微动适配器修改可在下一轮生效，原始日志记录实际加载SHA。

加载器3项测试通过：新版本不改变旧引用、语法失败不破坏旧模块、缺少入口拒绝。使能窗口专项测试及实机复测结果随后追加。

## 实测结果

适配器31项测试通过，新增4项覆盖一次0.6°偏移通过、超过3°拒绝、持续漂移拒绝、其他轴仍0.2°。连同旧接管适配器合计50项通过。

实机归档`20260906_175623_320_position_microprobe_worker_c5fe9e1a`确认加载SHA `a7009ad3a579061872d025f00a748de359634ce4251f6f172591178b3ff7b1d2`。四轴落稳均通过，耗时约1.57、1.40、1.41、1.37秒；M3参考点从-16.0°更新为-15.8°，未因小抖动停机。随后升流检查M4回复后附加M1错误`0100ee6b`，原始事务被拒绝，未进入正式往返段。最终四轴失能确认及完整配置恢复均通过。

真实图：`qa/twin/com5-settling-measured.png`。本轮仍为接管/升流诊断，不是球心XY轨迹验收。

另发现自动重连并发缺陷：记录active期间，自动准备线程将auto改为error，消息“通讯恢复后的自动准备失败：自动流程运行中，请先按急停”。原因待修复处是`schedule_prepare_if_needed`将控制按钮锁定误认为需要准备，未排除微动worker。该缺陷应独立修复，但目前证据不能证明它导致M1协议错误（微动worker持有SERIAL_LOCK）。

## 自动重连修复与第二轮复测

`schedule_prepare_if_needed`已增加空闲状态、AUTO_THREAD、活跃记录及急停检查；排队的线程执行前持有AUTO_REQUEST_LOCK再次检查，异常只在原状态未改变时写入。独立AST测试5项通过，与原idle_scan测试合计9项通过。已正常加载到后台。

第二轮`20260906_180200_341_position_microprobe_worker_9ad1cc44`再次四轴落稳通过，M3偏移0.1°。轮询证据`qa/twin/reprepare-fixed-runtime.json`显示记录活跃时一直保持position-microprobe，结束后才因M1错误转为error，没有再次出现自动准备异常覆盖。M3位置回包`0336010000009c6b`后附加`0100ee6b`；证明这项并发修复仍未解决独立通信错误。最终四轴失能及原配置恢复确认通过，未进入正式往返轨迹。
