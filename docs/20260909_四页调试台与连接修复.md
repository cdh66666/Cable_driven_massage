# 四页调试台与连接修复 · 2026-09-09

主入口仍为 `http://127.0.0.1:8787/`，底部切换改 ID、连接、校准、绘制。操作顺序和使用方法见 README。

## 代码入口

- `tools/y42_four_pages.js`：四页布局、自动发现、同号保留并改速、连接状态与暂停扫描。
- `tools/y42_pc_direct_web.py`：保留请求显式指定的临时探测速率；只读扫描不再覆盖正式通信端口/波特率。页面源码和四页脚本在 GET 时读取，可热更新。
- `tools/y42_real_lesson.html`：保留早期教学页，独立编号不要求四台准备成功。

## 修复的原因

先前请求封装用下拉框值覆盖了调用者的波特率，导致逐档扫描可能实际用了同一档。随后扫描请求又把后台正式速率改成最后扫描的速率，使921600设备被用512000查询，产生无回包提示。

现在正式通信固定921600，探测/迁移显式传入临时速率。点击连接先停止正在进行的周期扫描，等当前扫描请求结束再连接。连接成功后暂停状态保存在浏览器中，同源标签页通过存储事件同步；刷新不会自动重启扫描。失败后的重新扫描是显式操作。用户本轮反馈该版本使用正常；这不代替所有硬件状态的验证。

后端已有的 `prepare` 流程负责四台在线、X 固件复核、物理按键锁定和失能 ACK；前端只在返回 `ready=true` 后报告连接完成。改 ID 页允许同号，仅统一/验证波特率，不发送无意义的同号改名命令。
