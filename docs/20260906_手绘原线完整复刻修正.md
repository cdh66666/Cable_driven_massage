# 手绘原线完整复刻修正

用户要求：完整复刻原始手绘折线，不加平滑、简化、圆角。原始点数和顺序必须保留；可沿原线插点，不能删拐点换速度。

## 实际问题与修改

1. 画布原先过滤小于0.15mm的移动。已取消，并接收浏览器getCoalescedEvents中的采样点；不再裁剪越界坐标，越界原笔画保留并明确拒绝提交。
2. 控制器原先再次按0.05mm距离过滤。已取消，含微小移动、重复点和末尾点的完整输入原序保留。
3. resample_polyline原先超过6000点后均匀抽点，可能删原始拐点。现在按剩余点数预算分配新增插点，原始顶点精确保留；若原始输入自身超限，明确拒绝，不抽点。
4. 蛇形、十字路径剩余Chaikin调用已移除。
5. 仿真返回完整source_points，设备提交使用这些原始点，避免把取整后的加密仿真点当成用户输入。
6. 仅保留数组还不够：原100Hz时间采样会跨过不在10ms时钟上的拐点。严格手绘采用共享的y42_exact_path.exact_vertex_profile，每个原始顶点为10ms整数时刻，逐段零速到零速，只调整时间，不改几何。加密显示点不作为额外停点。三角速度曲线满足峰值速度2d/T、加速度4d/T²上限；允许变慢。下发迟到时停止，禁止原有追赶逻辑跳点。
7. 仿真采用同一顶点对时函数。仿真与控制器的加速度参数仍各自显式设定，因此相同输入不意味着所有物理假设或时长自动相同；不把模型位姿曲线当作输入原线。

## 证据

`qa/twin/exact-handwriting.png/json`使用历史归档保存的真实用户笔画输入：108个原始点全部按原顺序、精确坐标保留，加密558点，折线长度差0。生产源码的实际100Hz笛卡尔目标序列也逐一包含所有108个原始顶点；JSON保存完整输入、规划、下发目标、时间和SHA256。

26项相关隔离测试通过：真实生产转换与规划AST、微小锯齿/重复点/闭合末尾点、点数预算、100Hz不跨角、速度与加速度上限、多笔阶段、物理模型。

无头浏览器合并事件测试：5个原始采样（含小于旧阈值的移动）全部保留，仿真后提交payload与原始输入逐项一致，页面脚本错误0；设备发送请求在测试中被拦截，没有发送到硬件。

本次没有运行设备绘制轨迹；既有通信故障和无效标定仍未解决。上述1:1是数字输入、几何规划和正常时钟下的笛卡尔目标保真验证，不是“真实球心零误差”的验收。

修改已正常部署到控制器与孪生界面。设备停稳失能，未绕过任何标定或运动保护。
