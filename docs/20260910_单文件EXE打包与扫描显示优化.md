# 20260910 单文件 EXE 打包与扫描显示优化

## 目标

把 `tools/y42_pc_direct_web.py` 上位机打包成**单个可双击的 `Y42调试台.exe`**：
双击后自动打开浏览器调试页，无黑框窗口；拷到别的电脑/别的目录（含下载文件夹）也能直接用。

## 打包方案（packaging/）

- `launcher.py`：窗口化启动器。启动即占位页（"正在启动，页面会自动刷新"），业务模块装载完成后热替换为真页面，双击后 1 秒内浏览器就有反馈；托盘图标退出；日志写 EXE 同级 `Y42调试台_数据/Y42调试台_日志.txt`。
  - Windows 命名互斥体单实例：任何目录重复双击，都会把已在运行的页面调出来，而不是静默退出或起第二个实例。
  - 登记文件 `%LOCALAPPDATA%\Y42Console\server.json`（原子写），跨目录发现已在运行的实例；强杀残留的登记会在下次启动自动清理。
  - `SO_EXCLUSIVEADDRUSE` 独占绑定：Windows 默认 `SO_REUSEADDR` 允许两个进程绑同一端口，会出现"第二实例页面空白"的假故障。
- `build_exe.py` / `_rebuild.py`：PyInstaller `--onefile --windowed --noupx`；`_rebuild.py` 输出到全新目录（`_build2`/`dist_new`），**零删除重建**，不碰旧产物。
- `_verify_delivery.py`：交付前 8 场景矩阵（中文目录 / 下载文件夹 / 双实例调起 / 端口被占 / 只读目录 / 随机端口双开 / 同文件重复双击 / 残留登记清理），全部自动断言。

## 扫描显示优化（tools/y42_four_pages.js）

用户实测反馈的两个问题：

1. **点"重新扫描"第一次只显示 ID 1，再点一下才全部显示。**
   根因：旧扫描顺序是先扫完「ID 0–1 × 全部串口 × 9 档波特率」（实测每档约 1.3 s，共 20 s 以上）才轮到 ID 2–10；且每次点击都会中止当前进度从头再来。
   修复：改为**波特率优先、ID 1–10 一次扫全**——第一遍（921600）约 2 秒即可点亮全部设备；扫描进行中重复点击不再重启，提示"正在扫描中（已发现 N 台）"。
2. **四台都在线时设备条不显示，误以为没扫到。**
   根因：一键连接成功后自动扫描停止，此时刷新页面设备列表为空。
   修复：已连接状态下直接用 `/api/auto` 的实时遥测恢复设备条（不发扫描请求），并注明"已连接：显示实时遥测在线的 N 台"。

其他：
- 扫描状态行高亮 + 步数进度（"正在扫描 COM25 · 921600（第 1/9 档）· 已发现 4 台"）。
- 手动选择的串口持久化（`y42.port`），启动恢复；不在线回退推荐口；USB 转换器串口优先扫描。
- `tools/y42_pc_direct_web.py`：新增 `set-port` / `port-diagnose`（只读自检）、串口快照与推荐口识别（`likely_adapter`）。

## 遗留提醒

- 总线曾出现"打开串口正常但 RX=0"与后台 `Cannot configure port (OSError 87)` 卡死：独立进程能打开同一串口，说明是应用内句柄状态问题；总线静默时仍需检查电机供电、RS485 A/B 与共地。
- 未签名 EXE 首次运行会被 SmartScreen/杀软拦截，需"更多信息 → 仍要运行"。
